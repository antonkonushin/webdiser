# Живая версия докторской диссертации

Черновой электронный текст Антона Конушина. Сайт сохраняет оформление `chapter-template`:
типографику, палитру, формулы, рисунки и навигацию по главам.

Адрес после публикации: https://antonkonushin.github.io/webdiser/

## Что редактировать

Основные авторские исходники находятся в соседнем хранилище `MyDiser/Диссертация`.
Каждый раздел — отдельный Markdown-файл. Шесть папок `Глава X. …` лежат непосредственно в `Диссертация`.
Порядок задаёт `book.yaml`. Метаданные раздела: `id`, `title`, `status`, `source_notes`.

`content/` — автоматически подготовленный публикуемый снимок; `docs/` — готовые страницы.
Оба каталога хранятся в Git. Установки и временные файлы находятся в `.build/` и не публикуются.
Сборка из снимка не обращается к исходному хранилищу и воспроизводится на другом компьютере.

В Git попадают только выбранные в оглавлении тексты, библиография и используемые ресурсы.
`Рабочие-заметки`, невыбранные заметки, полный архив статей и локальные пути не переносятся.
Проверяйте изменения `content/` перед публикацией: этот снимок доступен читателям репозитория.

## Установка

Python 3.10+; Pandoc поставляется внутри пакета `pypandoc_binary`.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

На macOS/Linux используйте `.venv/bin/python` вместо `.venv/Scripts/python.exe`.

В текущем рабочем окружении зависимости также установлены в `.build/python`;
`build.py` автоматически находит эту папку.

## Обновление из авторских исходников

Из папки `MyDiserProject/web`:

```powershell
.venv/Scripts/python.exe build.py --source "../../MyDiser/Диссертация"
.venv/Scripts/python.exe -m http.server 8000 --directory docs
```

Откройте http://localhost:8000/. После правки и новой сборки обновите страницу браузера.
Сборка не отправляет изменения на GitHub автоматически.

## Воспроизведение версии из Git

```powershell
.venv/Scripts/python.exe build.py
.venv/Scripts/python.exe build.py --check
.venv/Scripts/python.exe scripts/test_build.py
```

Сборщик останавливается при неизвестных ссылках, пропавших файлах, дублях идентификаторов,
выходе за пределы каталога исходников и предупреждениях Pandoc.
Страницы и снимок обновляются только после проверки подготовленного сайта.
`docs/build-manifest.json` содержит хеши исходников, версию Pandoc и результаты проверки.
Редакция определяется содержимым входных файлов, а не временем запуска.

## Формат текста

```markdown
---
id: my-section
title: Название раздела
status: draft
source_notes:
  - Концепция дисера.md
---

Текст раздела и формула $x_i$.

[Связанный раздел](section:scene-task).
[Глава](page:camera-geometry).

![Содержательная подпись](figures/example.svg){#fig-example}

Источник [@paper-key].

### Подраздел {#stable-subsection-id}
```

В теле не нужен заголовок `#` или `##`: название и номер раздела создаются автоматически.
`status`: `outline` — план; `draft` — черновик; `review` — на обсуждении; `ready` — текст подготовлен.
Это состояние текста, а не статус публикации или подтверждение научной новизны.
Нумерация разделов следует оглавлению. Постоянный `id` сохраняйте при переименовании и переносе.

Картинки и ссылки на дополнительные файлы задавайте относительно Markdown-файла.
Таблицы — Markdown; формулы — LaTeX. Не используйте Obsidian-wikilinks и абсолютные локальные пути.
Для интерактивного примера предусмотрите статическое изображение, пригодное для печатной версии.
Формулы сейчас требуют интернет для загрузки MathJax 3.2.2; остальной текст и ресурсы локальны.

## Обсуждение

У каждого раздела есть постоянная ссылка и кнопка, открывающая **форму** GitHub Issue.
Адрес раздела и редакция подставляются в форму. Сообщение отправляет сам читатель;
для отправки нужна учётная запись GitHub. Новую редакцию можно сопоставить с историей Git.

## Публикация

GitHub Pages публикует ветку `main`, папку `/docs`. В `docs/` есть `.nojekyll`.
После проверки:

```powershell
git add content docs build.py templates static scripts README.md requirements.txt .gitignore
git commit -m "Update dissertation draft"
git push origin main
```

Сохраняйте вместе изменения исходников, шаблонов и результата сборки.
Не редактируйте HTML в `docs/` вручную. Настройку Pages выполняют один раз в Settings → Pages.

## Будущая печатная версия

```powershell
.venv/Scripts/python.exe build.py --export latex
.venv/Scripts/python.exe build.py --export docx
```

Результаты находятся в `.build/exports/`. Это технический экспорт общего текста:
нормативная вёрстка диссертации, автоматические ссылки на номера рисунков/формул,
сквозная печатная нумерация и оформление библиографии пока не реализованы.
Для LaTeX PDF требуется отдельный движок и согласованный шаблон организации.
Автореферат ведётся отдельной краткой редакцией, сейчас создан его план.

## Происхождение первой версии

Основа — «Концепция дисера», планы геометрической и семантической частей,
библиографические подборки и «Концепция и план докторской диссертации».
Новая нумерация устраняет две главы с номером 2 в концепции, сохраняя порядок содержания.
Первый черновик не содержит новых численных результатов. Библиография перенесена из локального
каталога без новой проверки статусов и версий; неизвестные поля не дополнялись догадками.
